# Tarefa 1 — Ciclo manual de 5 livros técnicos

## Status

Pendente.

## Objetivo

Validar manualmente quais tags realmente ajudam devs e tech leads antes de criar schema, automação, backfill ou skill local.

## Método

1. Escolher cinco ebooks técnicos disponíveis e diversos.
2. Para cada livro, propor no máximo três tags visíveis.
3. Registrar tags alternativas rejeitadas e o motivo da rejeição.
4. Testar as dimensões candidatas: stack, área/problema, uso editorial e nível.
5. Decidir se nível deve virar tag visível, campo separado, metadado interno ou ficar fora da v1.
6. Observar se as tags escolhidas poderiam alimentar vitrines transversais na home.
7. Registrar fricções, dúvidas e regras aprendidas para uma futura skill local de tagging editorial.

## Livros

A lista deve ser escolhida no início do ciclo, priorizando diversidade dentro do catálogo técnico:

- um livro de linguagem ou framework;
- um livro de infraestrutura, cloud ou DevOps;
- um livro de dados, IA ou estatística;
- um livro de arquitetura, engenharia de software ou práticas;
- um livro técnico que seja ambíguo o suficiente para testar limites do vocabulário.

## Registro esperado por livro

```text
Livro:
Categoria atual:
Tags escolhidas, no máximo 3:
Alternativas rejeitadas:
Dimensões cobertas:
Valor esperado para devs/tech leads:
Dúvidas editoriais:
```

## Critérios de pronto

- cinco livros avaliados com até três tags cada;
- racional das tags e rejeições registrado;
- vocabulário v0 proposto;
- decisão documentada sobre nível e uso editorial;
- possíveis vitrines por tag anotadas;
- regras e fricções prontas para virar skill local em etapa posterior.

## Fora de escopo

- criar ou alterar banco;
- automatizar sugestão por IA;
- publicar tags na PDP;
- fazer backfill;
- criar a skill local antes de fechar o ciclo manual.
